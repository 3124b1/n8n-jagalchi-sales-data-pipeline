## 1. 실행 구조

원본에는 Code 12개, HTTP Request 7개, Google Sheets 8개, Schedule Trigger 1개, Google Sheets Trigger 1개, Merge 1개, 설명 메모 5개가 있다.
Code 노드 추출본은 [목록](../src/n8n-code/index.json)에서 찾을 수 있다.

05시 실행 설정이 있으나 원본 JSON에는 워크플로 시간대가 명시되지 않았다. 한국시간 05시로 운영하려면 인스턴스 또는 워크플로 시간대를 확인해야 한다.

## 2. 카페24 주문 → 품목 행

- API: orders, embed=items, 페이지당 100건
- offset을 100씩 증가시키고 응답 주문이 100건 미만이면 종료
- 요청 상한 80회 설정이 있어 상한 도달 시 전체 수집 여부 확인 필요
- paid=F 제외, paid=T이면서 결제금액 0인 주문 제외
- 주문의 items를 펼쳐 품목별 행 생성
- 상품명: 특수 예외 → 콜라보 → 김스낵·건어물의 세트/단품 → 어종 키워드 → 일반 정리
- 품목별 주문번호 기준으로 갱신·추가

[품목 정리 코드](../src/n8n-code/01-cafe24-order-items.js)

### 금액의 분석 단위

‘총 주문금액’과 ‘총 결제금액’은 주문 단위 값이 품목 행마다 반복된다. 품목 테이블에서 단순 합산하면 중복될 수 있다.

주문 매출은 주문번호별 일관성을 확인하고 주문 단위로 집계해야 한다. ‘상품별판매액’은 (상품가+옵션가)×수량이며 할인·배송비 등을 반영한 실결제 배분액과 같다고 가정하면 안 된다.

## 3. 네이버 주문

- 새 행 추가 감지: 1분 폴링 설정
- 상품주문번호 없는 행 제외
- 주문상태 ‘구매확정’만 유지, 클레임상태 ‘취소철회’ 제외
- 날짜와 상품명 정리 후 수량 숫자 변환
- 상품주문번호 기준 갱신·추가

원본의 입력 감지와 출력은 같은 문서의 NAVER 탭이다.

카페24의 결제 기준과 네이버의 구매확정 기준은 다르다.

## 4. 월별 고객 집계

1. 주문 API에서 buyer를 함께 조회
2. 유효 주문의 회원 ID를 중복 제거해 100개씩 조회
3. 회원 ID로 생년월일·성별을 주문과 결합
4. 주문번호 중복 제거
5. 월·성별·연령대별 구매자 식별값 집합, 주문 건수, 결제금액 집계
6. 대상 월마다 남성 6개·여성 6개 연령대와 알수없음 1개, 총 13개 조합을 생성

연령은 주문 연도−출생 연도인 연 나이 기준이다. 정확한 만 나이와 다를 수 있고 비정상 생년월일에 대한 별도 검증은 부족하다.

성별·연령 중 하나라도 모르면 모두 알수없음으로 묶는다.

구매자 식별 우선순위는 회원 ID → 이메일 → 이름과 연락처 → 주문번호이다.

## 5. 통합 고객 스키마

| 필드 | 의미·주의 |
| --- | --- |
| row_key | 월_채널_성별_연령대 |
| data_month | YYYY-MM |
| channel | cafe24 또는 naver |
| gender / age_group | 집계 구간 |
| visitors_count | 카페24 고객 집계에는 없어 공란 |
| buyers_count | 카페24 식별값 기반 집계 / 네이버 결제고객수 |
| order_count | 네이버 고객 리포트에는 없어 공란 |
| order_amount | 카페24 결제금액 / 네이버 판매금액(총), 의미 차이 확인 필요 |
| collected_at | 변환 시점 |

네이버 ‘전체합산’ 행은 제외해 상세 집단과 이중 집계하지 않는다. 콤마·원 등이 포함된 숫자를 변환하지만 잘못된 숫자나 일부 결측을 0으로 처리하도록 하였다.

## 6. 조회 기간과 적재

| 흐름 | 조회 기간 | 저장 키·방식 |
| --- | --- | --- |
| 품목 주문 | 정기 최근 7일 / 수동 2025-06-01부터 월별 | 품목별 주문번호, 갱신·추가 |
| 고객 집계 | 정기 지난달·이번 달 / 수동 2025-01-01부터 월별 | 월×성별×연령대 및 채널 포함 키, 갱신·추가 |
| 일별 방문·매출 | 전일 | 추가 |
| 도메인 | 전일 | 날짜와 도메인으로 키를 생성하지만 저장은 추가 |

방문·매출은 두 API 응답을 위치 기준 Merge 후 처리한다.

도메인은 방문 목록에 매출 목록을 도메인으로 결합하며, 방문 목록에 없는 매출 전용 도메인은 출력하지 않는다.

## 7. 스프레드시트에서 중복 데이터 정리

데이터를 다시 불러오거나 추가로 업로드하는 과정에서 같은 데이터가 반복해서 입력될 수 있어, 스프레드시트에 UNIQUE 함수를 적용했다. 지정한 범위에서 중복을 제외한 고유한 행을 반환하도록 구성했다.

이 처리는 n8n의 데이터 저장 이후 스프레드시트에서 수행하므로, 워크플로 JSON과 Code 노드 추출본에는 포함되어 있지 않다.
