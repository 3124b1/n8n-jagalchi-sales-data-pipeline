# 프로젝트 경험: 운영 환경을 고려한 판매 데이터 파이프라인 설계

[프로젝트 소개](../README.md)

## 문제와 나의 역할

기업은 여러 판매 채널의 현황을 한눈에 확인할 수 있는 대시보드를 필요로 했습니다. 하지만 채널마다 상품명과 옵션 표기, 데이터 구조, 거래 상태와 제공 지표가 달라, 먼저 데이터를 어떤 기준으로 정리하고 연결할지 결정해야 했습니다.

프로젝트가 끝난 뒤 시스템을 사용할 담당자의 업무 환경도 중요했습니다. 기업에는 데이터 시스템을 전담하는 개발자가 없었기 때문에, 기존 업무 방식과 익숙한 도구를 고려해 운영 부담을 줄이고자 했습니다.

저는 4인 팀에서 데이터 자동 취합 파이프라인 설계를 주력으로 맡았습니다. 채널별 수집 방식 파악, 상품명 표준화, n8n과 API를 활용한 수집·처리 흐름, Google Sheets 저장 구조와 BI 연동을 담당했습니다. KPI 선정, 특이 거래의 처리 기준, 대시보드 검수와 인수인계는 팀원 및 기업 담당자와 협업했습니다.

## 수행 과정

### 1. 채널별 제약에 맞춰 수집 방식을 정했습니다

카페24에서는 API로 주문·회원정보와 방문·매출·유입 데이터를 수집하는 흐름을 구성했습니다. 필요한 지표가 바로 제공되는지, 여러 데이터를 결합해야 계산할 수 있는지를 먼저 확인했습니다.

네이버는 당시 인증과 파일 처리상의 제약을 고려해, 담당자가 기존 방식대로 데이터를 내려받아 지정 시트에 입력하면 이후 정제가 자동으로 진행되도록 구성했습니다. 두 채널에 같은 수집 방식을 적용하기보다, 확보할 수 있는 데이터와 담당자의 업무 흐름에 맞춰 자동화 범위를 정했습니다.

### 2. 상품과 거래를 해석하는 기준을 정리했습니다

같은 상품도 채널에 따라 상품명과 옵션이 다르게 표현됐습니다. 상품명 정제 과정에서는 옵션에 포함된 제품명, 세트·단품 여부, 콜라보 표기, 어종 등을 반영했습니다. 구체적인 상품명이 일반적인 키워드로 잘못 분류되지 않도록 규칙의 적용 순서도 고려했습니다.

거래 데이터는 상태와 금액만으로 성격을 단정하기 어려운 경우가 있었습니다. 기업 담당자와 특이 거래의 성격을 확인하고, 테스트 결제와 실제 판매를 구분하기 위한 처리 기준을 협의했습니다.

### 3. 집계 단위와 지표의 의미를 구분했습니다

고객 지표는 카페24 주문과 회원정보를 결합해 월·성별·연령대별로 집계했습니다. 같은 고객이 여러 번 주문할 수 있으므로 구매자 수와 주문 수를 별도로 계산했습니다.

채널 간 지표를 연결할 때는 컬럼 이름뿐 아니라 집계 기준도 살폈습니다. 카페24의 결제 기준과 네이버의 구매확정 기준을 구분하고, 해당 고객 리포트에서 제공되지 않는 지표는 0으로 채우지 않고 공란으로 남겼습니다. 데이터 형식을 통일하더라도 지표의 의미까지 같아지는 것은 아니라는 점을 고려했습니다.

### 4. 저장 이후의 처리와 인수인계까지 연결했습니다

주문과 고객 집계는 식별키를 기준으로 기존 데이터를 갱신하거나 새로운 데이터를 추가하도록 구성했습니다. 일별 방문·매출과 유입 도메인 데이터는 새 행을 추가하는 방식으로 저장했습니다.

데이터를 다시 불러오거나 업로드하는 과정에서 발생하는 중복에 대해서는 스프레드시트의 UNIQUE 함수를 활용해, 지정한 범위에서 중복을 제외한 결과를 구성했습니다.

정리된 데이터는 Google Sheets와 BI 도구를 연결해 조회할 수 있도록 했습니다. 팀은 사용 가이드와 인수인계 문서를 마련하고, 기업 담당자에게 사용 방법을 전달했습니다.

## 유지보수에 대한 생각

프로젝트를 진행하며 ‘내가 이 기업의 직원이라면 이 시스템을 어떻게 받아들일까’를 계속 생각했습니다. 새로운 도구를 배우는 부담은 어느 정도인지, 화면에 표시된 수치의 기준을 이해할 수 있는지, 문제가 생기면 어디를 확인해야 하는지가 중요했습니다.

이러한 고민은 도구 선택뿐 아니라 수집 범위, 데이터 처리 기준, 문서화에도 영향을 주었습니다. 특히 담당자가 익숙한 구글 생태계를 활용하고, 수집부터 대시보드까지 데이터가 어떻게 이어지는지 설명할 수 있도록 정리하는 데 신경 썼습니다.

이 경험을 통해 유지보수는 개발이 끝난 뒤의 수정 작업에만 해당하는 것이 아니라, 처음부터 사용자의 환경을 이해하고 운영 가능한 구조를 설계하는 일이라는 점을 배웠습니다.

## 결과와 배운 점

카페24와 네이버의 판매 데이터를 수집·정제하고, 7개 KPI를 5개 대시보드 페이지로 구성했습니다. 사용 가이드와 함께 결과물을 전달하고, 2026년 8월 18일 대면 인수인계를 진행했습니다.

제가 이 프로젝트에서 배운 것은 데이터 수집 자동화와 함께, 수집된 값을 어떤 기준으로 해석하고 집계할지 정하는 일이 중요하다는 점입니다. 상품을 구분하는 규칙, 구매자와 주문을 세는 단위, 채널별 지표의 차이가 대시보드에 표시되는 수치의 의미를 결정했습니다.

앞으로도 데이터를 다룰 때는 처리 결과뿐 아니라 그 결과를 사용하는 사람이 기준을 이해하고 업무에 활용할 수 있는지까지 고려하고자 합니다.
